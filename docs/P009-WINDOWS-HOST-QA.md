## Correction to the actual source
Original `Source/PluginProcessor.cpp` exposed `getNumPrograms()==1` and
`getProgramName(0)==""`. It was a true plugin SDK compliance error, not a
sample/firmware issue. The processor now returns the descriptive host
placeholder `Akai S3000XL` for program index zero and an empty string for
invalid indices. This **does not create a real Akai program/keygroup** and
must not be mistaken for original-ROM program assignment.

[Commit 06cfae4](https://github.com/challanger2000/125A-Akai-S3000XL-VST3/commit/06cfae4ecbf7c1131335ceae455e197b6c2ebcce)
also integrates the complete original 125A v0.3.2 tester plus Steinberg
validator **into the real full Windows build workflow**. From now on the
full build must compile, run the actual tester and independently report
zero FAIL/zero WARNING/official validator PASS before its status is green.
On failure the actual host QA report is preserved as an artifact.

## P010 – ROM-overlay compilation and strict VST3 metadata (2026-11-20)
- [Windows build 44830555826](https://github.com/challanger2000/125A-Akai-S3000XL-VST3/actions/runs/44830555826) reached and passed **the full MAME static library build and CMake configure**, then **FAILED** compiling the overlay-enabled VST3: `Source/PluginProcessor.cpp:3298` called `juce::String::add`, which does not exist. Both mutually exclusive ROM-source branches now set the diagnostic `juce::String` by assignment. This is a real C++ compile correction, not an emulator pass.
- The previously linked 125A VST3 also contains a non-strict `moduleinfo.json` generated by pinned JUCE 8.0.12: eight trailing commas in object/array fields. Python's strict `json.loads` rejects this manifest; the earlier plugin host tolerated it. To avoid relying on permissive parsing, `scripts/build/validate_moduleinfo.py` removes only trailing commas **outside strings**, validates the exact 125A identity and two VST3 classes, rewrites strict canonical JSON and validates again. The full Windows workflow applies this to the built module **before** uploading the artifact.
- Private owner-only ROM packaging now also applies the same metadata canonicalization; it still verifies both original V2.0 ROM SHA256 digests and leaves all PE image bytes unchanged.
- **NOT yet PASS:** the revised full Windows VST3 build, its new Steinberg validator run, private ROM boot, original firmware sample recording, audible MIDI output and DAW recall all require new direct evidence. A new Windows build must complete before any success claim.
